# 修改参数后恢复网格

适用：`auto_grid_futures_generic.py`（现货/逐仓）、
`auto_grid_contract_futures_generic.py`（合约多头）、
`auto_grid_contract_futures_short_generic.py`（合约空头）。

停止旧进程，修改入口文件的参数，然后继续使用 `startup_mode="resume"`，
沿用原数据库。不要为参数变更使用 `reset`。部署时三个公共程序文件需一起更新。

## 哪些参数影响旧订单

- 金额、杠杆、止盈比例或网格窗口数量修改后可恢复。新的开仓订单使用新配置，
  旧订单不按新金额缩放。止盈比例单独变化不会改写已有周期的计划止盈价。
- 只有 `grid_step_pct` 改变时，重排未止盈周期。
- 旧数据库没有历史配置：首次升级也按当前网格重排，以后通过 `grid_layouts`
  表判断间距是否变化。相同参数反复启动不会反复移动目标价。
- 参考价单独改变不会触发旧止盈重排；它会影响新开仓格。
- 账户类型、合约结算币或多空方向不能共用同一个已记录配置的策略。
  同一交易对有多个未完成策略仍需人工处理，不会自动合并。

## 止盈重排规则

1. 先核对实际订单状态，暂不启动交易维护线程。
2. 撤销原止盈委托并处理撤单期间的实际成交。完全止盈的周期不再重排；
   部分成交只保留剩余数量。
3. 多头按旧止盈价从低到高排序，从最低价严格上方的最近新网格开始，
   每个周期依次分配一个更高格；空头相反，从最高价严格下方开始逐格降低。
   同价位周期按记录 ID 排序，价格按交易所最小报价单位取整，跳过重复格。
4. 对应开仓格为目标价相邻的内侧格：多头低一格，空头高一格。
   该格以及目标止盈价被独占，直到周期完全平仓。
   不能往这些位置补开仓单。每个开仓格固定至多一个活动周期（待成交开仓单或未止盈持仓），不再提供每格多单数量参数。
5. 真实开仓价 `buy_price`、成交订单 ID、数量保留；独占位置另存于
   `grid_open_price`，不会用新格价覆盖真实成交历史。

程序采用百分比等比网格，不是固定价差网格。例如多头参考价 100、
间距 2%，新格向上依次约为 100、102.04、104.12、106.25。
旧止盈价为 101、103、103 的三个周期重排到 102.04、104.12、106.25，
对应占用开仓格 100、102.04、104.12。

重排是以最近旧目标价为共同起点，并不为每笔旧仓分别保证原止盈价或保本价。
如果旧订单分布很疏，新分配的远端订单目标价可能比其原目标价更近。

## 现有挂单与异常恢复

- 原开仓挂单如果仍在新网格且没有占用重排位置，保留其订单及数量。
  不在新网格或冲突的开仓挂单会撤销；撤单中若已有部分成交，实际持仓也参与重排。
  后续补出的订单才使用新的金额。
- 重排只分配目标价和占位。实际挂止盈仍遵守原来的止盈窗口、止盈挂单总数上限、
  最小订单数量及真实可用仓位检查，不会把窗口外的所有止盈同时发到交易所。
- 数据库先保存待迁移配置，撤单完成后一次事务更新目标价及占位。
  撤单超时或状态不确定时停止启动，不会一边保留未知旧止盈一边下重复新单。
  再次 `resume` 会继续待完成的迁移。
- 不需要删除数据库。建议升级前在停机状态下备份 SQLite 数据库，
  包含尚未合并的 WAL 文件；不要在运行中手工修改订单表。
