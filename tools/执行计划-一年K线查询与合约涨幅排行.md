# 执行计划：一年 1h K 线查询与合约涨幅排行

## 1. 需求理解

### 1.1 用户原始需求

> 在 `tools/` 文件夹创建两个非 CLI 文件：第一个输入交易对及现货/合约类型，查询近一年的 1h K 线；第二个查询合约交易对，计算每个交易对最近一年从最低点到现价的涨幅，并按降序排序。

### 1.2 我的理解

本需求需要提供可被其他 Python 代码直接导入调用的函数或类，不提供 `argparse`、命令行参数解析或交互式输入。第一个模块接收明确的市场类型（仅允许 `spot` 或 `futures`）和交易对，使用 Gate API 公共接口取得滚动最近 365 天的 1h K 线，并将现货与合约的不同响应结构标准化。第二个模块查询指定结算币种下所有可交易、未进入下架流程的永续合约，复用第一个模块取得一年 1h K 线，以一年最低 K 线低价和当前成交价计算涨幅，最后降序返回全部有效结果。

默认计算公式为：

```text
涨幅百分比 = (当前价格 - 最近一年最低价) / 最近一年最低价 × 100
```

“现价”暂按合约信息中的 `last_price` 解释；当该字段缺失或无效时，回退到时间最新的 1h K 线收盘价。时间范围暂按调用时刻向前滚动 365 天解释，而不是自然年度。

### 1.3 实现目标

- 目标 1：在 `tools/` 新增统一的一年 1h K 线查询模块，同时支持 Gate 现货和永续合约。
- 目标 2：正确处理一年约 8760 根 K 线超过单次接口上限的问题，实现按时间窗口分页、边界去重和时间排序。
- 目标 3：在 `tools/` 新增合约涨幅排行模块，查询全部活跃合约并按一年最低点至现价的涨幅降序返回。
- 目标 4：所有核心逻辑均可通过函数调用和依赖注入测试，不依赖 API Key，不产生 CLI 副作用。
- 目标 5：为分页、响应标准化、涨幅计算、排序、异常隔离和边界条件补充自动化测试。

### 1.4 非目标范围

以下内容本次不处理，除非用户另行要求：

- 不增加命令行入口、交互式输入、Web 页面或定时任务。
- 不查询或筛选币种市值、成交额、资金费率等额外指标。
- 不把结果写入数据库、CSV、JSON 或 Excel；调用方可以自行持久化返回值。
- 不修改 OpenAPI Generator 生成的 `gate_api/api/` 或 `gate_api/models/` 文件。
- 不包含交割合约和期权；本计划中的“合约”指 `FuturesApi` 提供的永续合约。
- 不默认扫描多个结算市场；调用方通过 `settle` 指定，例如 `usdt` 或 `btc`。

### 2.2 尚未确认的信息

| 信息 | 为什么需要确认 | 不确认时的处理策略 |
|---|---|---|
| “近一年”是滚动 365 天还是同日减一年 | 闰年时起点可能相差一天 | 默认使用 `365 * 24 * 3600` 秒，并允许注入 `end_time`，文档明确该口径 |

| 是否需要限制返回前 N 名 | 用户只要求降序排序，没有指定数量 | 默认返回全部有效交易对，不截断；调用方可以对结果切片 |
| 网络失败时是整体失败还是跳过单个合约 | 全市场扫描中单个合约失败不应必然阻断全部结果 | 默认单个合约失败记录到 `errors`，其他合约继续；合约列表请求失败则整体抛出异常 |

## 3. 总体实现方案

采用“数据获取层 + 计算排行层”两层设计。数据获取层只负责根据 `market_type` 调用对应 Gate API、分段拉取最近 365 天 1h K 线，并输出统一字段。排行层通过 `list_futures_contracts()` 获取活跃合约，对每个合约调用数据获取层，计算区间最低 `low`、选择现价、计算涨幅并排序。API 对象、结束时间、重试参数和并发度均设计为可注入参数，以便测试确定性和调用方控制资源。

建议整体流程：

1. 校验并规范化市场类型、交易对、结算币和结束时间。
2. 将一年时间范围切成现货最多 1000 小时、合约最多 2000 小时的闭开时间段，逐段请求 1h K 线。
3. 把两类返回值标准化为相同结构，按时间戳去重、升序排列并裁剪到目标时间范围。
4. 查询活跃永续合约并逐个获取标准化 K 线，计算最低点至现价涨幅。
5. 按 `gain_pct` 降序排序，并同时返回失败合约的结构化错误，避免静默遗漏。

建议公共调用形式：

```python
from tools.market_candlesticks import get_one_year_hourly_candlesticks
from tools.rank_futures_yearly_gain import rank_futures_by_yearly_low_gain

spot_candles = get_one_year_hourly_candlesticks(
    market_type="spot",
    trading_pair="BTC_USDT",
)

futures_candles = get_one_year_hourly_candlesticks(
    market_type="futures",
    trading_pair="BTC_USDT",
    settle="usdt",
)

ranking = rank_futures_by_yearly_low_gain(settle="usdt")
```

建议 K 线标准输出字段：

```python
{
    "timestamp": 1787302800,
    "open": "123.45",
    "high": "125.00",
    "low": "120.10",
    "close": "124.20",
    "volume": "1000",
}
```

价格和成交量保留字符串，避免浮点精度丢失；涨幅计算内部使用 `Decimal`。

## 4. 详细执行步骤

### 步骤 1：定义公共接口、时间口径与标准数据结构

**执行目标：**  
明确两个非 CLI 模块的可调用接口、输入校验规则和返回协议，避免现货/合约响应差异泄漏给调用方。

**具体操作：**

1. 在 `tools/market_candlesticks.py` 定义 `get_one_year_hourly_candlesticks()`。
2. 参数至少包含 `market_type`、`trading_pair`、`settle="usdt"`、`end_time=None`，并允许注入 `spot_api`/`futures_api` 或统一客户端工厂。

5. 在 `tools/rank_futures_yearly_gain.py` 定义 `rank_futures_by_yearly_low_gain()`，默认返回包含 `results` 和 `errors` 的结构，以便调用方识别扫描是否完整。

**涉及文件 / 模块：**

- `tools/market_candlesticks.py`
- `tools/rank_futures_yearly_gain.py`

**输入：**

- 市场类型：`spot` 或 `futures`
- 交易对：例如 `BTC_USDT`
- 合约结算币：例如 `usdt`
- 可选结束时间 Unix 秒时间戳

**输出：**

- 标准化的一年 1h K 线列表
- 按涨幅降序排列的合约结果与失败明细

**完成标准：**

### 步骤 2：实现一年 1h 时间窗口分页

**执行目标：**  
完整获取约 8760 根 1h K 线，不触发 Gate 单次返回数量上限。

**具体操作：**

1. 计算 `end = int(end_time or time.time())`，再计算 `start = end - 365 * 24 * 3600`。
2. 将结束时间对齐到小时边界，并明确是否包含当前尚未收盘的小时；建议默认仅返回时间戳落在 `[start, end)` 的 K 线。
3. 现货按每段不超过 1000 小时切分，合约按每段不超过 2000 小时切分；请求使用 `_from`、`to`、`interval="1h"`，不同时传 `limit`。
4. 相邻段保留可控的边界重叠，最终以时间戳为键去重，防止 Gate 的 `to` 边界包含规则造成重复或缺失。
5. 对每段响应检查时间戳范围，丢弃目标窗口外数据，并在合并后按时间升序排列。
6. 为网络超时、Gate 限流和临时服务错误增加有限次数重试及指数退避；参数错误、交易对不存在等不可重试错误直接抛出。

**涉及文件 / 模块：**

- `tools/market_candlesticks.py`
- `gate_api/api/spot_api.py`（仅调用，不修改）
- `gate_api/api/futures_api.py`（仅调用，不修改）

**输入：**

- 目标开始/结束时间
- 市场类型对应的单次最大数据量
- Gate API 实例

**输出：**

- 按时间顺序生成的分页请求区间
- 合并去重后的原始 K 线集合

**完成标准：**

- 一年范围不会使用单次请求完成。
- 现货每个窗口不超过 1000 小时，合约每个窗口不超过 2000 小时。
- 相邻窗口边界不存在重复时间戳，且不会保留范围外数据。
- `end_time` 固定时，请求区间和结果完全确定。

**本步骤验证方式：**

1. 分页数量验证
   - 方法：使用 Fake API 记录所有 `_from`、`to` 和 `interval` 参数。
   - 预期结果：现货一年至少拆为 9 段，合约一年至少拆为 5 段；所有请求均使用 `1h` 且未传 `limit`。
2. 边界去重验证
   - 方法：让相邻两个模拟响应都返回边界时间戳。
   - 预期结果：最终结果中该时间戳只出现一次，整体严格按时间升序。
3. 范围裁剪验证
   - 方法：模拟响应额外返回开始时间之前、结束时间之后的数据。
   - 预期结果：输出只包含目标 `[start, end)` 范围内数据。
4. 重试验证
   - 方法：模拟第一次请求超时、第二次成功，以及持续不可重试参数错误。
   - 预期结果：临时错误按上限重试并成功返回；不可重试错误立即向调用方传播。

### 步骤 3：实现现货与合约 K 线标准化

**执行目标：**  
把现货数组响应和合约对象响应转换为统一、可计算的数据结构。

**具体操作：**

1. 为现货响应建立集中解析函数，按当前 Gate SDK 返回顺序读取时间戳、开高低收和成交量，不在排行代码中直接使用数组下标。
2. 为 `FuturesCandlestick` 建立解析函数，读取 `t/o/h/l/c/v`。
3. 将时间戳转换为整数；用 `Decimal` 验证 `open/high/low/close` 可解析且价格大于 0，再以规范字符串输出。
4. 对空响应返回空列表；对单根字段缺失或非数字数据，采用明确策略：默认跳过坏 K 线并在可选诊断信息中记录，而不是污染最低价计算。
5. 关闭函数内部创建的 `ApiClient`；由调用方注入的 API/客户端不在函数中关闭。

**涉及文件 / 模块：**

- `tools/market_candlesticks.py`
- `gate_api/models/futures_candlestick.py`（只读取结构）

**输入：**

- `SpotApi.list_candlesticks()` 的数组响应
- `FuturesApi.list_futures_candlesticks()` 的对象响应

**输出：**

- 字段一致的 K 线字典列表

**完成标准：**

- 现货和合约对同一组 OHLC 测试数据产生相同标准字段。
- 无效价格不会参与最低价计算。
- 内部客户端在成功和异常路径均被关闭，外部注入对象保持可用。

**本步骤验证方式：**

1. 响应映射验证
   - 方法：分别构造一根现货数组 K 线和一根 `FuturesCandlestick` 风格对象。
   - 预期结果：两者转换后的 `timestamp/open/high/low/close/volume` 完全符合预设值。
2. 无效数据验证
   - 方法：传入缺字段、`low="0"`、非数字价格和空响应。
   - 预期结果：坏记录被排除或产生定义好的诊断信息；空响应得到空列表，不发生除零错误。
3. 资源生命周期验证
   - 方法：模拟内部创建客户端的正常返回和异常抛出。
   - 预期结果：两条路径均调用 `close()` 一次；注入 API 时不擅自关闭调用方资源。

### 步骤 4：实现活跃合约发现与一年涨幅计算

**执行目标：**  
扫描指定结算市场中的可交易永续合约，为每个合约计算一年最低点至现价的涨幅。

**具体操作：**

1. 调用 `FuturesApi.list_futures_contracts(settle)` 获取合约列表。
2. 仅保留 `status == "trading"` 且 `in_delisting` 不为真的合约；没有名称的异常记录跳过并记录原因。
3. 对每个合约调用 `get_one_year_hourly_candlesticks(market_type="futures", ...)`。
4. 取有效 K 线 `low` 的最小值作为 `year_low`，并记录其首次出现时间 `year_low_time`。
5. 优先用 `Contract.last_price` 作为 `current_price`；缺失、非数字或不大于 0 时回退到最新 K 线 `close`。
6. 使用 `Decimal` 计算 `gain_pct`，输出时采用一致精度，例如保留 4 位小数或直接保留十进制字符串。
7. 输出至少包含 `contract`、`settle`、`year_low`、`year_low_time`、`current_price`、`current_price_source`、`gain_pct`、`data_start_time`、`data_end_time`、`candle_count`。
8. 按 `gain_pct` 降序排序；涨幅相同则按合约名升序，保证结果稳定。

**涉及文件 / 模块：**

- `tools/rank_futures_yearly_gain.py`
- `tools/market_candlesticks.py`
- `gate_api/api/futures_api.py`（只调用）
- `gate_api/models/contract.py`（只读取结构）

**输入：**

- 结算币种 `settle`
- 可选固定结束时间
- Gate `FuturesApi` 或可测试的注入对象

**输出：**

- 降序排列的合约涨幅结果
- 无数据或查询失败的合约错误明细

**完成标准：**

- 使用 K 线最低价而不是最低收盘价。
- 计算公式和零值保护正确。
- 已下架、下架中、非交易状态合约不参与。
- 一个合约失败不影响其他合约生成结果。

**本步骤验证方式：**

1. 公式验证
   - 方法：模拟最低价 10、现价 25。
   - 预期结果：`gain_pct` 为 150%，且最低点时间与最低 K 线一致。
2. 现价回退验证
   - 方法：分别提供合法 `last_price`、空值、零值和非数字值。
   - 预期结果：合法时来源为 `contract_last_price`；无效时使用最新 K 线收盘价并标注来源。
3. 合约状态过滤验证
   - 方法：混合 `trading`、非交易、`in_delisting=True` 合约。

### 步骤 5：控制全市场扫描性能与错误隔离

**执行目标：**

**具体操作：**

3. 对 Gate 限流响应和临时网络错误使用有上限的指数退避，并加入轻微抖动，避免所有任务同步重试。
4. 对结果统一在主线程排序，避免完成顺序影响输出。
5. 支持注入进度回调，例如 `progress_callback(completed, total, contract, error)`，但默认不打印日志，保持库函数特性。
6. 汇总 `requested_contracts`、`successful_contracts`、`failed_contracts`，使调用方能够判断结果完整度。

**涉及文件 / 模块：**

## 7. 风险点

| 风险 | 影响 | 规避方式 | 验证方式 |
|---|---|---|---|
| 一年 1h 数据请求量很大 | 全市场可能产生“合约数 × 至少 5”次请求，耗时或触发限流 | 有界并发、超时、有限重试、退避、进度回调和失败汇总 | 统计调用次数、最大并发、限流模拟与小规模实测 |
| Gate 分页边界包含规则不明确 | 重复或漏掉边界小时 | 请求区间轻微重叠，最终按时间戳去重并裁剪 | 构造边界重复/缺失测试，抽查连续时间戳 |
| 现货数组字段位置容易误读 | OHLC 映射错误，排行结果失真 | 把解析集中在一个函数，并依据当前 SDK 文档/真实响应锁定测试样例 | 使用已知 OHLC 响应逐字段断言 |
| 当前未收盘 K 线 | 最低价可能随当前小时变化，重复调用结果不稳定 | 明确 `[start, end)` 口径，默认排除未完成小时或通过固定结束时间控制 | 小时边界测试和固定时间重复调用 |
| `last_price` 与 K 线时间不同步 | 可能出现现价低于所取最低价等异常 | 输出价格来源与数据时间，保留诊断字段；必要时回退最新收盘价 | 构造不同步数据并验证标记 |
| 新上市、停牌或无成交合约数据不足 | 不具备完整一年可比性 | 返回覆盖起止时间和数量，由调用方决定是否过滤 | 新上市短区间测试 |
| 同名函数或 `tools` 包与第三方包冲突 | 导入到错误模块 | 从项目根目录运行并使用明确模块路径；必要时后续改更具体包名 | 检查 `module.__file__` 和导入测试 |
| Python 2 历史声明与新工具代码风格 | 若强制 Python 2，类型注解和现代并发写法不可用 | 实现前确认运行版本；默认以当前测试环境 Python 3 为目标，若需 Python 2 则避免注解/dataclass/f-string | 在目标 Python 版本执行 `py_compile` 和测试 |
| 实网测试结果随市场变化 | 无法对具体涨幅做固定断言 | 自动化测试全部使用 Fake API 和固定时间，实网仅做协议冒烟测试 | 对实网只断言结构、排序和公式自洽 |
